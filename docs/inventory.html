Commands skills you run

/runway:setup
Checks what runway needs in this repository and, with your approval at each step, writes runway.json and fills the gaps: a Checks section in CLAUDE.md, REVIEW.md, .worktreeinclude, the epics folder. Tells you what runway can't do here.
/runway:epic-plan <brief>
Plans an epic: an epic file (data model, interfaces, release, slices) and a skipped end-to-end test, reviewed with you, then pushed on epic/<epic-name> with a draft PR.
/runway:epic-next
Builds the next slice of the epic in progress (add its name if there are several): merges the base branch in, spec, implement, verify, slice review, then marks it done and pushes.
/runway:epic-auto
Builds every remaining slice unattended, then ships the PR ready for review. /runway:epic-auto status and /runway:epic-auto stop check on it or stop it.
/runway:spec <task> [--go]
Numbered acceptance criteria, a file-level plan and a risk level, in a fresh worktree; waits for your approval (unless --go), then runs implement.
/runway:implement
Test-first, one test file and its criteria at a time, a commit per green step; then runs verify. Run it yourself after a /clear: it works from the saved spec in .runway/specs/ on Sonnet at medium effort. Approving inside spec also runs it, on the session's model.
/runway:verify
The verify command, the relevant e2e tests, and each criterion checked in a headless browser, one Playwright script per journey, with screenshots. Loops until green.
/runway:ship
Code review, plus a security review for epics, medium or high risk, or a diff touching securityPaths; fixes, verify again, then opens the PR (or, for an epic, fills in its PR and marks it ready). If something went wrong more than once, the PR proposes one line for the repository's docs (or a check that would catch it); you decide. Never merges.

Skill Claude uses on its own

conventions
Before Claude writes code in an area, sends it to the repository's CLAUDE.md, the docs it links, REVIEW.md and neighbouring files, and keeps comments to the few the code can't do without (never history or decisions).

Agents each starts with a fresh context

explorer
Haiku · read onlyMaps the code a task touches and the closest pattern to copy. Used by epic-plan and spec.
test-writer
Opus · reads, writes tests, runs themWrites tests from the criteria that fail for the right reason, and commits them before any code. Used by implement.
test-auditor
Sonnet · breaks code, runs tests, restoresBreaks the code behind each criterion and reports tests that still pass. Used by ship for epics and medium or high risk.
reviewer
your model · reads, runs git and testsChecks a diff against the criteria, REVIEW.md and the epic; reports verified findings only, no style or minor points. Used per slice and by ship.
security-reviewer
your model · reads, runs git and testsChecks authorization, input validation, injection, secrets and data exposure. Used per slice and by ship when the risk or the paths touched call for it, and always by ship for an epic.

Hooks run by Claude Code in every session, including unattended ones

session-start.mjs
when a session startsKeeps runway's output (.claude/worktrees/ .claude/screenshots/ .claude/logs/ .runway/specs/ .playwright-mcp/) out of git through .git/info/exclude. Where runway isn't set up, says once to run /runway:setup; reports invalid settings every time.
guard-bash.mjs
before a shell commandBlocks force pushes, pushing to or deleting the base branch, reset --hard, clean -f, discarding the working tree, dropping stashes, DROP TABLE, ORM resets, skipping git hooks, gh pr merge, gh pr create outside ship and epic-plan, and wiping a root or home folder. A speed bump, not a security boundary.
post-edit.mjs
after a file editFormats and lints the file with the repository's own Biome, or Prettier + ESLint (only when the repository configures them); errors left after safe fixes go back to Claude.
stop-gate.mjs
when Claude tries to stopWith any changes, runs the verify command and sends Claude back to work until it passes, up to three tries in a row; then Claude may stop and you're told. A tree that already passed, unchanged since, isn't verified again. Changes that were already there when the session started (your own work in progress) don't count, and Claude may stop to ask you something by ending its message with a RUNWAY-ASK: line.

The stop and edit hooks do nothing in a repository without a runway.json.

Scripts, templates and the browser server

config.mjs
Finds and validates the repository's runway.json; the skills run it to read the settings, and ship runs it with --security-files to decide on the security review.
doctor.mjs
The checks behind /runway:setup and epic-auto's branch-rules warning.
prepare-worktree.mjs
Run first by spec, epic-plan and epic-next (which then run the verify command once, so a base branch that is already broken stops the work instead of becoming Claude's problem): moves a main-checkout session into a fresh worktree, never leaves an existing one, puts epic work on epic/<epic-name>, and removes worktrees whose PR is merged or closed and whose commits are pushed.
epic-auto.mjs epic-auto-lib.mjs
The unattended runner (plain code, no model): starts headless Claude sessions, waits for CI, waits out usage limits. Never merges. The lib holds its prompts, slice parsing and the tools its sessions may use.
schemas/runway.schema.json
The schema of runway.json.
templates/
The epic file, the PR description, a starter REVIEW.md, and a GitHub ruleset that blocks force pushes, deletion and pushes without a PR on the default branch.
.mcp.json
The Playwright browser server (headless, pinned version) that verify drives. It starts in every session where runway is enabled, one reason to enable runway per project.
