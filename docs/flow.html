What runs at each step: what you run, what is in context, and which skills, agents, scripts and hooks take part. An epic is built in slices on one branch, epic/<epic-name>, and lands as one PR. runway never merges: you do, after your review. Every piece on its own: runway inventory.

When it stops (a session reporting something only you can do, CI it cannot fix, a diverged branch): the reason is in .git/runway/epic-auto-<epic-name>.json. Fix it and say proceed. A usage limit only pauses it until the reset. Nothing is ever merged by the runner.

Hooks in every session, including headless ones

guard-bash.mjs
before a shell command
blocks force pushes, pushing to or deleting the base branch, reset --hard, clean -f, discarding the whole tree, stash drop, DROP, ORM resets, skipped git hooks, gh pr merge, gh pr create outside ship and epic-plan, rm -rf of root/home. A speed bump, not a security boundary
post-edit.mjs
after a file edit
formats and lints the file with the repository's own Biome or Prettier + ESLint; leftover errors go back to Claude
stop-gate.mjs
before Claude stops
with any changes (new files too) since the session started, runs the verify command; a failure keeps Claude working, up to three tries in a row. A RUNWAY-ASK: line lets Claude stop to ask you
session-start.mjs
when a session starts
keeps .claude/worktrees, .claude/screenshots, .claude/logs, .runway/specs and .playwright-mcp out of git; points to /runway:setup where needed
