# Review rules

What every change must follow. runway's reviewer agents check each diff against this list; keep it short and
specific to this repository.

## Correctness
- Every acceptance criterion has a test that proves it, or is tagged `[manual: ...]` because no automated test is practical.
- Errors are handled where they occur or passed on deliberately; nothing is swallowed silently.

## Security
- Every route or handler that reads or changes data checks the caller's session and scopes queries to their user
  or tenant.
- All external input (bodies, params, headers, webhooks, third-party responses) is validated before use.
- No secrets in code, logs, URLs or client bundles; new config goes through the config schema.

## Data
- Migrations are generated by the project's tool, never edited after they are applied, and work while the previous
  release still runs.

## Conventions
- Follows CLAUDE.md and the docs it links; generated files are never edited by hand.
- Comments only where the code can't say it (a deliberate choice, a trap, an invisible reason); no history or
  decisions in comments.
- No new dependency, service or pattern without a reason in the PR description.
